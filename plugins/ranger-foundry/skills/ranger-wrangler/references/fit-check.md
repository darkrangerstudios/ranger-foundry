# Effort preflight

The agent can recommend a route wherever these instructions are loaded. Native
controls determine whether it can apply or verify a change. Prose alone does not
change compute or give a product native skill discovery.

Run inline before costly work, a material task/risk change, or a settings question.
Reuse a fresh caller receipt when host, model, user choice, task class and limits
match. Skip tools, research, workers and prompts for an unchanged fit or trivial
follow-up. A sibling skill call does not restart the check.

1. **Observe** the product/surface, model/provider, effort or mode, supported
   choices and overrides using available evidence. Keep requested,
   configured/user-reported and runtime-verified values distinct. Hidden fields
   remain unknown; wording, speed, response length and self-report are not proof.
2. **Assess** consequences, uncertainty, tool/context needs and remaining limits.
   Recommend lower effort after difficult work ends or higher effort for a real
   reasoning gap. Keep explicit user pins. Use an approved map or label advice
   **proposal only**; for effort-only choices read [effort guidance](effort-control.md).
   For a model/provider recommendation, load Wrangler's route and data-permission
   method. A name alone does not establish availability or quality. Missing
   authentication, tools or input do not justify extra reasoning or a provider escape.
3. **Act or advise.** Use an already-authorized supported native control, or give
   one brief proposal: observed state/confidence, supported choice, task reason,
   exact host steps and effective boundary. Read only the relevant recipe in
   [host controls](host-controls.md) when a change needs instructions. Identify
   the product/surface if ambiguous. No equivalent control means advisory only.
   Do not equate product levels/modes, silently override pins/defaults, spend a
   reset credit, or spawn a worker for this check. Preserve spend and destination
   authority; recommending a route is not permission to activate it.
4. **Resume safely.** Before suggesting interruption, checkpoint completed work,
   in-flight actions and the next step. Let active writes reach a known safe
   state; reconcile uncertain outcomes instead of replaying them. Use the host's
   actual boundary, then read available resolved diagnostics. Unknown effective
   settings remain unverified. Keep owner, budget and worker/escalation counts
   across stop/resume and skill/model changes.

Keep a reusable receipt in existing task state only when useful: host/model,
observed setting and evidence status, task class, recommendation/basis,
applied-versus-verified state, boundary, owner and remaining limits. Stay quiet
when the fit is adequate. Repeat advice only after a material change or a user
request; respect an explicit decline. Unsupported controls alone do not stop safe
work at an already-authorized setting. Preserve Wrangler's stops for dependent
high-risk or hard-budget-sensitive work. Neither effort direction removes tests,
permissions, independent review or release gates.

Example: “High is selected; execution is unverified. Medium is a reasonable
proposal for this mechanical edit. Use the app's effort control before the next
request; keep High if you prefer.” Never present this proposal as calibration,
measured savings or confirmation that the setting changed.
